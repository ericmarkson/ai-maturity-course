LLM Inference Optimization: KV-Cache, Speculative Decoding & Serving

Learning objective: Explain why autoregressive LLM decode is memory-bandwidth bound while prefill is compute bound, calculate KV-cache VRAM from model dimensions and batch/context parameters, and combine GQA/FP8 KV quantization, PagedAttention, continuous batching, and speculative decoding to meet latency and cost SLOs.

Definition

LLM inference optimization is the systems and architectural discipline of minimizing Time-To-First-Token (TTFT), Inter-Token Latency (ITL), and serving cost per token without degrading model quality. Because Transformer generation splits into two physically distinct phases — parallel prompt prefill and sequential token-by-token decode — production engines must balance GPU compute saturation, HBM memory capacity, and HBM memory bandwidth.

How It Works

During prefill, all S prompt tokens are processed together using large matrix-matrix multiplications (GEMMs), yielding high arithmetic intensity that saturates GPU Tensor Cores (compute-bound). During autoregressive decode, generating one new token per request reduces projections to matrix-vector operations (GEMVs): the GPU must stream every model weight and cached Key/Value tensor from HBM into on-chip SRAM just to produce one token per sequence, leaving Tensor Cores mostly idle (HBM memory-bandwidth bound).

Caching past Key and Value projections avoids recomputing earlier tokens, but exact KV-cache VRAM grows linearly with layers (L), KV heads (Hkv), head dimension (dhead), sequence length (S), batch size (B), and precision bytes: 

KV_VRAM_bytes = 2 * L * H_kv * d_head * S * B * bytes_per_elem

Modern inference stacks attack both the capacity ceiling and the bandwidth bottleneck simultaneously:

  • Attention KV compression (MQA / GQA / MLA) & FP8 KV quantization: Multi-Query Attention (1 KV head) and Grouped-Query Attention (e.g., 8 KV heads shared across 64 query heads) slash Hkv by 4×–16×, while Multi-Head Latent Attention (MLA) compresses KV into a low-rank latent vector. Quantizing KV entries from FP16 (2 B) to FP8/INT8 (1 B) halves remaining KV memory.
  • PagedAttention & Prefix Caching: PagedAttention (vLLM) allocates KV storage in fixed-size, non-contiguous memory blocks via a block table — eliminating internal buffer fragmentation — and lets concurrent requests share read-only blocks for common system prompts or RAG prefixes.
  • Continuous (iteration-level) batching: Inserts new requests and evicts completed sequences at every decode step rather than stalling an entire batch on the longest output.
  • Speculative decoding: A tiny fast draft model proposes γ tokens sequentially; the target model scores all γ + 1 positions in a single parallel verification pass (nearly the same memory-bandwidth time as 1 decode step). Modified rejection sampling preserves the target model's mathematically exact output distribution.

Worked Example

Consider a 70B GQA-8 model (L = 80, Hkv = 8, dhead = 128) in FP16 (2 bytes). Per token, KV-cache requires: 2 × 80 × 8 × 128 × 2 = 327,680 bytes (~328 KB, or 320 KiB/token — 8× smaller than MHA's 2.5 MiB/token). At context S = 8,192 and batch B = 32, KV-cache alone consumes 327,680 × 8,192 × 32 ≈ 85.9 GB (80.0 GiB). Switching to FP8 KV halves this to 42.9 GB, and a 50% shared prefix cache drops it further to ~22.1 GB.

On decode latency, suppose a small draft model generates γ = 4 tokens at relative step cost cdraft = 0.06 and achieves acceptance rate α = 0.75. Expected accepted tokens per verification pass are (1 − 0.755) / (1 − 0.75) = 3.05 tokens, giving net speedup 3.05 / (1 + 4 × 0.06) ≈ 2.46× with zero quality degradation.

Common Pitfall

Static max-length KV allocation & high-batch speculative slowdown: Pre-allocating contiguous KV buffers up to max_model_len wastes 60–80% of HBM on unused padding, capping batch size B and starving throughput. Conversely, enabling speculative decoding at large batch sizes (B ≥ 64) can actually increase latency: verifying γ × B tokens at once pushes the GPU from memory-bandwidth bound into compute-bound territory, erasing the "free parallel verification" advantage.
