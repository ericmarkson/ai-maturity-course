Rigorous Eval Design: LLM-as-Judge and Statistical Significance

Learning objective: Diagnose and mitigate LLM-as-judge biases (position, verbosity, self-preference), calibrate automated judges against human labels using Cohen's kappa (κ), and apply confidence intervals, paired significance tests, and sample-size planning to eval comparisons.

Definition

Rigorous eval design combines calibrated automated scoring (including LLM-as-judge rubrics) with inferential statistics so model and prompt comparisons reflect genuine capability gains rather than judge bias or finite-sample noise. Without calibration and statistical power, teams ship regressions disguised as "+2% improvements."

How It Works

Scaling evaluations reliably requires guarding both the measurement instrument (the judge) and the statistical inference:

  • Judge bias mitigation: Pairwise and rubric LLM judges exhibit systematic distortions: position bias (favoring Option A or B regardless of content — mitigated by running swapped order A|B and B|A and keeping only consistent wins or averaging), verbosity bias (preferring longer, padded responses), and self-preference bias (scoring outputs from the judge's own model family higher).
  • Judge calibration (Cohen's κ): Validate automated verdicts on a stratified human-annotated golden set using Cohen's kappa, κ = (p_o − p_e) / (1 − p_e), which adjusts raw agreement po for chance agreement pe (unlike raw % accuracy, which misleads on imbalanced pass/fail datasets). Target κ ≥ 0.75–0.80 before trusting automated runs.
  • Statistical significance & paired power: Standard error shrinks as 1 / √N: SE = √(p(1 − p) / N). Running Candidate A and Candidate B on the exact same prompts allows paired testing (paired bootstrap resampling or McNemar's test), canceling item-difficulty variance and yielding tighter CIs than independent two-proportion tests.

Worked Example

Suppose Model B beats Model A on 11 of 20 prompts (55.0% win rate vs. 50% coin-flip baseline). With N = 20, the standard error is √(0.55 × 0.45 / 20) ≈ 11.1%, giving a 95% CI of [33.2%, 76.8%] (p ≈ 0.65). That "+5 pp win" is completely buried in sampling noise.

Now assume the true win rate is 58% and you scale the paired eval to N = 400 prompts: SE ≈ √(0.58 × 0.42 / 400) = 2.47%, tightening the 95% CI to [53.2%, 62.8%] and clearing p = 0.0014 < 0.05. Similarly, running an A/B order-swap check flags position bias immediately if the judge changes its winner whenever A and B swap slots.

Common Pitfall

Multiple-comparison p-hacking & raw % calibration illusions: Tweaking a prompt 15 times against a small 30-example dev set until one run hits p = 0.04 yields a 1 − 0.9515 ≈ 54% chance of a pure false positive unless you adjust thresholds or confirm on a held-out test split. Likewise, celebrating "90% raw agreement" with human raters on a dataset where 90% of answers pass masks a collapsed judge with Cohen's κ ≈ 0.
