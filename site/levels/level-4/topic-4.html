Intro to NLP: Tokenization, Embeddings, word2vec

Learning objective: Trace how raw text becomes token IDs and dense embedding vectors—the same input representation modern LLMs start from—explain why one-hot vectors fail, and interpret vector arithmetic like king − man + woman ≈ queen.

Definition

Every modern language model begins by turning raw text into numbers in two steps. First, tokenization splits text into integer-indexed pieces (words or subwords like "un" + "friend" + "liness"). Next, an embedding table maps each token ID to a dense vector of floats where words used in similar contexts land near one another—a distributional idea pioneered cleanly by word2vec and still forming Layer 0 of today's LLMs.

How It Works

1. Tokenization (Subwords Over Whole Words): Whole-word vocabularies explode on typos, code, or rare compounds; character-by-character splits stretch sequences too long. Modern tokenizers (like Byte-Pair Encoding, BPE) keep frequent words as single tokens while splitting rare words into common subword pieces, balancing compact sequence length with zero "unknown word" failures.

2. Why One-Hot Vectors Fall Short: A 50,000-word vocabulary encoded as one-hot vectors uses 50,000-element arrays containing 49,999 zeros and a single 1. Every pair of words is orthogonal (dot = 0), meaning the geometry gives zero hint that "dog" is closer to "puppy" than to "toaster".

3. Dense Embeddings & Neighbor Prediction (word2vec → LLMs): Instead of sparse 50,000-D flags, an embedding lookup assigns each token a compact vector (say 300 to 4,096 numbers). Algorithms like word2vec learn these coordinates from raw text without human labels by predicting neighboring words from a center word (or vice versa): words that share contexts get pulled into shared semantic directions, which modern transformer LLMs then contextualize further via self-attention.

Worked Example: Why Similarity Works in Dense Space

Imagine three vocabulary tokens in a tiny 3D embedding space [royalty, animal, gender_female]:

  • king = [0.95, 0.0, 0.05], man = [0.05, 0.0, 0.05] → king − man = [0.90, 0.0, 0.0] (the pure "royalty" offset)
  • woman = [0.05, 0.0, 0.95] → king − man + woman = [0.95, 0.0, 0.95] ≈ queen

Because context prediction encodes concepts along consistent vector directions rather than isolated IDs, simple linear algebra reveals relational structure automatically.

Common Pitfall: Static Token Vectors & Tokenizer Blind Spots

Fixed word-level embeddings like word2vec store one vector per spelling—so "bank" blends riverbanks and financial banks into one averaged point (transformer attention resolves this dynamically from context). Meanwhile, because LLMs never see raw characters directly—only subword token IDs—unusual subword splits explain why LLMs sometimes struggle to count letters in a word or reverse spellings reliably.
