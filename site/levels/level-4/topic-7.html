Level 4 — Intermediate

PyTorch/TensorFlow Basics

Learning objective: Explain what tensors and automatic differentiation (autograd) handle behind the scenes in PyTorch and TensorFlow, trace the exact four-step training loop order, and avoid classic gradient accumulation bugs.

Definition

Deep learning frameworks like PyTorch and TensorFlow/Keras provide two core building blocks so engineers don't hand-code calculus or GPU kernels: tensors (multi-dimensional arrays that run fast on accelerators) and automatic differentiation (recording forward math so backpropagation gradients are computed automatically).

How It Works

1. Tensors Beyond NumPy: A tensor generalizes a NumPy ndarray—holding scalars, vectors, image batches (B, C, H, W), or token sequences (B, T, D)—while supporting GPU memory placement and optional gradient tracking.

2. Automatic Differentiation (Autograd): Whenever gradient tracking is enabled on model weights, every forward operation appends a node to a dynamic computation graph. Calling loss.backward() walks that graph backward via the chain rule and fills each parameter's .grad buffer automatically.

3. Standard 4-Step Training Loop: Regardless of framework style (PyTorch's explicit Python loop or Keras's higher-level model.fit()), every gradient-descent batch executes the exact same cycle: Forward pass → Compute loss → Backward pass → Update weights.

Worked Example: Minimal PyTorch Batch Step

for x_batch, y_batch in train_loader:
    optimizer.zero_grad()          # Clear gradients left over from prior batch
    preds = model(x_batch)         # 1. Forward pass: compute predictions
    loss = loss_fn(preds, y_batch) # 2. Compute scalar loss
    loss.backward()                # 3. Backward pass: autograd fills .grad
    optimizer.step()               # 4. Update weights using .grad & lr

During validation/evaluation, wrapping inference in model.eval() and with torch.no_grad(): skips building the computation graph, cutting memory use and turning off training-only behavior like dropout.

Common Pitfall: Forgetting zero_grad() or Leaving Training Mode On

In PyTorch, .backward() adds new gradients onto existing .grad tensors rather than overwriting them (useful for micro-batch accumulation, fatal by accident). Omitting optimizer.zero_grad() makes gradients sum endlessly across batches until training blows up. Similarly, forgetting model.eval() during validation keeps dropout active and distorts metrics.
