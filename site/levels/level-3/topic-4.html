Level 3 — Advanced Beginner

Feature Engineering and Data Cleaning

Learning objective: Diagnose dirty tabular data (missing cells, inconsistent strings, nominal categories, skewed numeric ranges), select appropriate imputation, encoding, and scaling transforms, and prevent preprocessing data leakage across train/test splits.

Definition

Data cleaning and feature engineering convert raw, messy tables into consistent, numeric representations that ML algorithms can optimize effectively. Often, cleanly engineered features (such as standardized scales, proper categorical encodings, and domain ratios) boost accuracy more than swapping model architectures.

How It Works

1. Imputing Missing Values: Rather than throwing away an entire row when one column is blank, imputation fills gaps with a column mean/median (for numbers) or mode/"Unknown" (for categories)—and often adds a binary was_missing flag when missingness itself carries signal.

2. One-Hot vs. Ordinal Encoding: Text categories must become numbers. Assign integers 1, 2, 3 only when order is real (Low < Medium < High). For nominal groups like Retail, Tech, Health, one-hot encoding creates separate 0/1 columns so the model doesn't falsely assume Health > Retail or Retail + Tech = Health.

3. Feature Scaling & Derived Features: Normalizing to [0, 1] or standardizing to mean 0, std 1 keeps large-unit features from drowning out small-unit features in distance models (k-NN, k-means) and speeds up gradient descent. Domain combinations—like turning raw timestamps into day_of_week or loan / income—expose relationships directly.

Worked Example: Why Unscaled Income Overwhelms Age in k-NN

Compare two customers in Euclidean distance: Ada (age=30, income=$60,000) and Bo (age=60, income=$60,500):

  • Unscaled: √((30−60)² + (60,000−60,500)²) = √(900 + 250,000) ≈ 500.9. A 30-year age gap contributes less than 0.2% of the distance!
  • Scaled to [0, 1] (ages 20–70, income $40k–$110k): age difference is 0.60 while income difference is 0.007—restoring age as a meaningful signal.

Common Pitfall: Data Leakage From Fitting Scalers Before Splitting

Never compute imputation means, min/max bounds, or standardization parameters across the combined dataset before splitting train and test sets. Using test-row averages inside training scalers leaks future distribution stats into training—always split first, fit transforms on train only, and apply those saved stats to val and test.
