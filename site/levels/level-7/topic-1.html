Level 7 — Advanced+

Agentic Systems: Tool Use, Function Calling, ReAct

Learning objective: The learner can trace a ReAct-style transcript and correctly label each step as "reasoning," "acting," or "observing," and can design a minimal tool schema for a given task.

Definition

Agentic systems are LLM-based programs that can decide to call external tools or functions and use the results to keep reasoning, instead of producing an answer in one single pass. Rather than guessing an answer from memory alone, the model can pause, invoke a tool (a calculator, a search engine, an API), read back what it returns, and fold that observation into its next thought.

How It Works

  • Function & Tool Schemas as Contracts: Each tool exposes a JSON Schema containing a name, a behavioral description explaining when to invoke it (and when not to), and typed parameters (enum, required, additionalProperties: false). The LLM never runs tools directly—it emits structured tool-call arguments that the host runtime validates and executes.
  • The ReAct Loop (Reason → Act → Observe → Repeat): Instead of guessing in one pass, the model writes an intermediate reasoning step (Thought), emits a tool call (Action) and stops generating, receives the runtime's execution output appended as a tool message (Observation), and repeats until it has enough verified facts to emit the final answer.
  • Structured Error Recovery & Retries: When an API times out, hits rate limits, or rejects malformed arguments, good agent runtimes catch the exception and feed a concise error string back as the Observation so the model can adjust arguments or choose an alternative tool—bounded by a strict max_steps budget.

Worked Example

For the task "Tokyo's current weather and 4 hotel nights at ¥18,000/night in USD at ¥155/$1": 

Thought 1: Current Tokyo weather changes constantly -> call weather_lookup.
Action 1:  weather_lookup(location="Tokyo")
Observe 1: "Tokyo: 26°C, light rain, humidity 78%."

Thought 2: Convert 4 × ¥18,000 / 155 with arithmetic tool to avoid rounding slips.
Action 2:  calculator(expression="18000*4/155")
Observe 2: "= 464.516... ≈ $464.52"

Thought 3: Both facts verified -> invoke finish_answer() with cited values.

Common Pitfall

Overlapping tool descriptions, missing step caps, and unguarded side effects. Exposing two near-identical tools (e.g., search_kb and query_docs) with vague descriptions causes tool thrashing; omitting a max_steps guard lets a model retry a failing call indefinitely, burning tokens and triggering duplicate writes if non-idempotent tools (like sending emails or charges) lack confirmation checks.
