Tracing and Observability for AI Systems

Learning objective: The learner can read a nested trace of an agent run, identify which span caused a slowdown or error, and list the minimum fields a useful LLM trace should capture.

Definition

Tracing/observability means capturing structured records of every step an AI system takes — prompts, tool calls, latencies, costs, errors — so the system can be debugged and monitored in production. One end-to-end run is represented as a tree of nested spans, each with a start time and duration, which can be visualized as a waterfall to spot exactly where time or money is being spent.

How It Works

  • Traces & Nested Span Trees: Every user request creates one end-to-end trace (trace_id) made of nested spans (span_id, parent_span_id, start timestamp, duration). Plotting spans as a waterfall immediately isolates whether latency lives in an LLM call, a slow vector search, or an internal sub-agent call.
  • OpenTelemetry GenAI Semantic Signals: Standardized span attributes capture gen_ai.request.model, prompt/completion token counts, computed USD cost, Time-to-First-Token (TTFT) vs. total latency, tool input/output payloads, and structured error codes—portable across observability backends (Langfuse, LangSmith, Arize, Jaeger).
  • Dashboards, Tail Latency (p95/p99) & Cost Attribution: Aggregating spans across production traffic tracks p95 latency (catching slow worst-case runs hidden by averages), per-step error rates, and cost per resolved task—linking live telemetry to online evals.

Worked Example

Inspect the 5-span trace in the waterfall below:

  • Baseline run: initial LLM (400 ms) → vector_search (150 ms) → subagent (300 ms, enclosing 250 ms child LLM) → final LLM (350 ms) = 1,200 ms total ($0.0062 across 900 tokens).
  • Injecting +1,000 ms into vector_search: That single tool span expands to 1,150 ms, pushing all downstream spans right to 2,200 ms total—making vector_search 52% of end-to-end latency.

Common Pitfall

Monitoring only mean latency and logging unredacted PII. Mean latency looks healthy even when 5% of users wait 18 seconds due to retries or oversized prompts (only p95/p99 catch this). Equally dangerous: writing raw prompts and tool outputs unredacted into trace stores leaks customer PII, auth tokens, or regulated health records—requiring automated PII scrubbing, retention limits, and trace sampling.
