Level 7 — Advanced+

Quantization and Distillation

Learning objective: The learner can explain why reducing precision from FP16 to INT8 shrinks model size, and can describe in one sentence what a distillation training loop optimizes for.

Definition

Quantization shrinks a model by storing its weights with fewer bits; distillation trains a smaller "student" model to mimic a larger "teacher" model — both trade some accuracy for speed, size, or cost. They're often combined: a distilled student model can then also be quantized for further savings.

How It Works

  • Weight Precision & Memory Bandwidth: Representing a 7B-parameter model in FP32 uses 28 GB (4 bytes/param); BF16/FP16 halves that to 14 GB; INT8 uses 7 GB; and INT4 uses ~3.5 GB. Because autoregressive decoding streams weights from GPU VRAM for every generated token (memory-bandwidth bound), shrinking bit width accelerates generation speed directly alongside memory savings.
  • PTQ vs. QAT & Activation Outliers: Post-Training Quantization (PTQ) calibrates scale factors (q = round(w / s) + z) on a small dataset after training; Quantization-Aware Training (QAT) simulates rounding noise during training so weights adapt. LLM quantizers like AWQ and SmoothQuant isolate high-magnitude activation outlier channels so 4-bit rounding doesn't wipe out sensitive features.
  • Knowledge Distillation (KL Loss on Teacher Logits): Trains a compact student model S to minimize KL divergence DKL(pT(·|x; τ) || pS(·|x; τ)) against a larger teacher T's temperature-softened output probabilities. Soft logits reveal relative probabilities across plausible runner-up tokens ("dark knowledge") that hard one-hot ground-truth labels discard.

Worked Example

Track combined compression starting from a 7B FP32 teacher (28 GB, 20 tok/s):

  • Step 1 — Distill to 50% student (3.5B): Halving parameters cuts FP32 size to 14 GB (7 GB in FP16) and doubles theoretical throughput.
  • Step 2 — Quantize student to INT4 (0.5 bytes/param): Footprint shrinks to 3.5B × 0.5 = 1.75 GB—a 16× reduction from 28 GB that comfortably fits on laptops or mobile NPUs while retaining strong fluency.

Common Pitfall

Naive min-max clipping on outliers and trusting perplexity alone. If one extreme outlier value (+14.0 vs. normal weights in [−0.3, +0.3]) stretches an INT4 tensor's min-max range, ordinary weights collapse into just 1–2 integer bins, ruining model quality. Furthermore, INT4 models can retain near-identical WikiText perplexity while silently breaking on multi-step math, code generation, or strict JSON tool calling—always run downstream task evals after quantizing!
