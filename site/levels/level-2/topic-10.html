The Modern AI Stack: Prompts, Rules, Tools (MCP), Skills & Memory

Learning objective: Separate the 7 building blocks of modern AI applications—Model, Prompt, Rules, Tools (MCP), Skills, Memory, and Agents—so you load the right piece at the right time without bloating context or leaving the AI helpless.

Definition

A capable AI setup is not "just one big prompt." It is a layered stack where each part plays a clean role: the Model supplies reasoning, the Prompt gives today's task, Rules set always-on boundaries, Tools (MCP) connect real external apps, Skills provide on-demand specialist playbooks, Memory recalls preferences across sessions, and an Agent coordinates multi-step loops.

How It Works (The Office & Kitchen Team Analogy)

Imagine hiring a sharp specialist into your office or restaurant kitchen. Giving them raw intelligence is not enough—they need instructions, manuals, equipment, and notes organized cleanly:

Stack Layer Office / Kitchen Analogy What It Actually Does When Loaded
Model The Specialist's Brain Predicts text, reasons, and writes code/prose Every inference call
Prompt Today's Work Ticket Specific goal & inputs for this request Current run
Rules (System) Standing Employee Handbook Always-on voice, formatting & safety policy Always on (every turn)
Tools / MCP Equipment & Software Apps Standardized connectors (SQL, Git, Slack, search) Called when action needed
Skills Laminated Recipe Binders / SOPs Step-by-step domain checklists & best practices On demand (only when relevant)
Memory Personal Filing Cabinet Facts & preferences remembered across chats Retrieved across sessions
Agent Autonomous Project Worker Loops over tools & feedback until goal passes Multi-step tasks only

Three Crucial Distinctions

  • Skill vs. Rules: Rules stay loaded on every single message, so they should stay short and universal (like brand tone or never leaking secrets). A Skill is a detailed domain SOP (e.g., a 200-line SQL migration guide) kept out of sight until a matching task appears—preventing everyday chats from getting slow and cluttered.
  • Skill vs. Tool (MCP): A Skill holds procedural know-how ("check locks before altering large tables"). A Tool / MCP server grants external capability ("actually query Postgres"). Reading a cooking binder does not give you a stove!
  • Skill vs. Agent: Write a Skill when you simply want reliable domain know-how applied on demand during a chat or workflow. Wrap it in an Agent only when the AI must loop on its own—calling tools, inspecting failures (like failing tests), and self-correcting over multiple steps.

Worked Example: Decluttering a Bloated SQL Setup

An engineering team pasted a 200-line zero-downtime Postgres migration checklist straight into their assistant's Global Rules. Two things broke: unrelated copywriting chats got slower and weirdly formal, and the AI still couldn't inspect production table sizes. Moving the checklist into an on-demand Skill (postgres-migration) kept everyday chats fast—and plugging in a read-only postgres-mcp Tool finally let the assistant verify real row counts before suggesting changes.

Common Pitfall: Global Rule Dumping & "Know-How Without Hands"

First, cramming niche SOPs into Global Rules causes context bloat: irrelevant instructions burn tokens on every turn and compete for the model's attention. Second, giving the model a rich Skill without connecting the matching MCP Tool leaves it reciting polished checklists it cannot execute.
