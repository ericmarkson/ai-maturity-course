Train/Validation/Test Splits

Learning objective: Explain why evaluating a model on its own training data gives a misleadingly optimistic result, using the train/validation/test framework correctly.

Definition

ML data is typically split into three parts: a training set the model actually learns from, a validation set used to tune choices along the way, and a test set kept completely separate until the very end, used to honestly measure how the model performs on data it has never seen.

Subtopics

  • Why you can't fairly evaluate a model on the same data it learned from
  • The role of the training set, validation set, and test set
  • Typical split ratios as a rule of thumb (e.g., 70/15/15 or 80/10/10)
  • Data leakage: the key failure mode where test data accidentally influences training
