Level 2 — Novice

Train/Validation/Test Splits

Learning objective: Explain why testing a model on its training data inflates accuracy, separate the distinct roles of training, validation, and test splits, and spot data leakage early.

Definition

Before training any model, teams divide their labeled dataset into three non-overlapping buckets: a training set to teach the model, a validation set to guide tuning choices along the way, and a sealed test set evaluated once at the end to measure honest real-world generalization.

How It Works (The Exam Analogy)

  • Training set (~70–80%) = Practice problems with the answer key: The model adjusts its internal weights by studying these examples repeatedly.
  • Validation set (~10–15%) = Practice mock quizzes: Whenever you compare two models or tweak settings, you grade them here so you don't fool yourself—without touching the final exam.
  • Test set (~10–15%) = The sealed final exam: Used once after all decisions are locked in. Testing a model on its own training set is like giving students the exact worksheet they memorized and claiming they mastered the subject.

Common Pitfall: Silent Data Leakage

Data leakage happens whenever information from the validation or test set sneaks into training—such as duplicate customer rows landing in both train and test, or normalizing features using averages from the whole dataset before splitting. Leakage produces glowing evaluation scores that collapse immediately on live users.
