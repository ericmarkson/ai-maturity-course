Designing an AI Team: Roles, Handoffs & Structured Processes

Learning objective: Replace brittle, overloaded generalist prompts with a structured AI team using clear roles, context isolation, role-scoped Skills/Tools, explicit Handoff Contracts, and an independent QA gate.

Definition

Designing an AI Team means splitting complex, multi-step work across specialized roles—typically Planner / Coordinator → Specialist Worker(s) → Independent QA Reviewer → Human Sign-off—connected by explicit Handoff Contracts and Context Isolation instead of stuffing every goal, raw log, and tool into one giant prompt.

How It Works (The Editorial Newsroom Analogy)

Imagine asking one staff member to interview 12 sources, dig through raw spreadsheets, write a front-page story, fact-check their own numbers, clear legal review, and hit "Publish"—all in one breathless hour. Mistakes slip through because no brain excels at messy exploration and strict final QA simultaneously.

  • Why 1 Overloaded Generalist Fails ("Context Rot"): When a single prompt holds competing goals, dozens of tools, and thousands of lines of noisy raw logs, attention gets diluted—what engineers call context rot. Middle instructions quietly drop, and asking that same cluttered thread to "double-check for mistakes" rarely catches its own blind spots.
  • Role Separation & Scoped Skills/Tools: Give each role only the Skill and Tools its job requires:
    • Planner / Coordinator: Breaks work into tasks and checks escalation flags (no publish/send tools).
    • Specialist Worker(s) / Subagents: Do focused heavy lifting (code fix, data audit, changelog draft) with their domain Skill + targeted read/draft tools.
    • Independent Reviewer / QA Gate: Opens a fresh context containing only the finished artifact, source evidence, and rubric—checking strictly without the writer's baggage.
    • Human Sign-off: Reviews escalations and approves external sends, deploys, or payouts.
  • Context Isolation: Let subagents read 200 messy log lines or 15 files inside their own isolated context and return only a crisp summary artifact—keeping the coordinator's desk clean.
  • Explicit Handoff Contracts: Every baton pass defines 4 items: (1) Exact Inputs, (2) Output Schema / Artifact, (3) Quality Bar, and (4) Stop / Escalation Rules (when to halt and ping a human instead of guessing).

Worked Example: Weekly Release Notes Handoff Contract

Instead of one giant prompt ("Read GitHub, write release notes, verify them, post to Slack"), pass a tight contract between roles:

Stage & Role Scoped Skill / Tools Handoff Contract (Output & Stop Rule)
1. Release Planner GitHub PR list (read-only) Outputs clean list of merged PR IDs + labels since v2.4. Stop rule: flag any PR labeled security for human lead.
2. Changelog Writer Release-Notes Skill; PR diff reader (no Slack tool) Outputs release-notes.md (Features, Fixes, Upgrade Steps) citing PR IDs only. Isolated context keeps raw diffs out of main thread.
3. Independent QA Gate QA Checklist Skill; PR titles (fresh context) Verifies every bullet matches a real PR ID and tone rule; fails draft if any claim is unverified or security flag missing.
4. Human Sign-off Publish / Slack Send button Reviews QA pass badge + flagged items, then clicks Send.

Common Pitfall: Giving Every Agent Every Tool & Self-Grading

Handing a research or drafting worker live email/deploy tools increases blast radius if it misinterprets noisy text (least-privilege scoping keeps dangerous buttons behind the final human gate). Similarly, asking the same model turn that generated a draft to "verify accuracy" fails far more often than passing the artifact to an Independent QA Gate in a fresh context.
