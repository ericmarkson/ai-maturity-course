Fine-Tuning Methods: LoRA, QLoRA, Full Fine-Tune

Learning objective: Learner can explain why LoRA/QLoRA drastically reduce the memory needed to fine-tune a large model compared to full fine-tuning, and can describe the rough quality/cost trade-off between the three approaches.

Definition

These are different techniques for adapting a pretrained model's weights to a new task, ranging from updating every parameter (full fine-tune) to updating only a small number of added parameters (LoRA/QLoRA) to save memory and cost.

How It Works

  • Full Fine-Tuning & Optimizer Memory: Updating all N parameters with mixed-precision AdamW stores BF16 weights (2N bytes), gradients (2N), FP32 master weights (4N), and two Adam moment buffers (8N)—requiring ~16 bytes per parameter before activations (roughly 112 GB+ for a 7B model, and over 1 TB for 70B).
  • LoRA (Low-Rank Adaptation): Freezes the pretrained weight matrix W0 ∈ Rd×k and learns a factored low-rank update ΔW = (α / r) · B · A, where A ∈ Rr×k and B ∈ Rd×r with rank r ≪ min(d, k) (typically 8–64). Because optimizer states and gradients are allocated only for A and B, trainable parameters drop by 99%+, and at inference time B · A can be merged into W0 with zero latency penalty. Variants like DoRA decompose magnitude and direction for extra accuracy.
  • QLoRA: Compresses the frozen base weights W0 into 4-bit NormalFloat (NF4, ~0.5 bytes/param) with double quantization of scaling constants and paged optimizer memory, dequantizing blocks to BF16 on the fly during forward/backward passes while keeping the tiny LoRA adapters in BF16.

Worked Example

Consider one attention projection matrix of shape 4096 × 4096 (16,777,216 parameters):

  • Full fine-tune: Trains all 16.78M parameters in that layer.
  • LoRA (rank r = 16): Trains A (16 × 4096) plus B (4096 × 16) = 131,072 parameters—a 128× reduction (0.78% of full).
  • Whole-model scaling (70B): Dropping from full fine-tuning (~1,400 GB) to LoRA (~160 GB) and 4-bit QLoRA (~48 GB) fits a 70B fine-tune onto a single 48 GB GPU, trading ~15% slower step time for on-the-fly 4-bit dequantization.

Common Pitfall

Using fine-tuning to store volatile facts or overlooking catastrophic forgetting. LoRA/QLoRA excel at adapting output format, tone, domain terminology, and tool syntax—not replacing RAG for rapidly changing facts. Meanwhile, training aggressively on a narrow dataset without mixing general replay data can degrade broad instruction-following (catastrophic forgetting), and setting rank r too low on complex multi-task objectives can underfit.
