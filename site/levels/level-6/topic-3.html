Level 6 — Advanced

Retrieval-Augmented Generation (RAG)

Learning objective: Learner can diagram the full RAG pipeline from a raw user question to a grounded answer, and explain one concrete failure mode (e.g., irrelevant chunk retrieved) and its effect on the final answer.

Definition

RAG is a technique where a language model's answer is grounded by first retrieving relevant documents/snippets from an external knowledge source and feeding them into the prompt, rather than relying purely on what the model memorized during training.

How It Works

  • 1. Ingestion & Chunking: Source documents are split into bounded chunks (often 256–512 tokens with 10–20% overlap) so facts straddling a boundary aren't severed. Each chunk is passed through an embedding model to produce a dense vector e(c) ∈ Rd and stored in a vector index alongside source metadata.
  • 2. Query Embedding & Top-k Search: At runtime, the user's question q is encoded by the exact same embedding model into e(q). Approximate Nearest Neighbor (ANN) search ranks chunks by cosine similarity (e(q) · e(c)) / (||e(q)|| ||e(c)||) and returns the top-k candidates.
  • 3. Prompt Augmentation & Grounded Generation: The retrieved snippets are inserted into the system/user prompt with explicit grounding rules (e.g., cite snippet IDs and abstain if no chunk answers the question). Because knowledge lives in the external index rather than model weights, updating a policy or adding private docs only requires re-indexing—not retraining.

Worked Example

Suppose a user asks: "How long are deleted files recoverable?"

  1. Embed & score: The retriever compares query tokens/embeddings against the 10-doc Nimbus knowledge base. Doc d7 (Deletion Policy) scores highest (exact overlap on deleted, files, recoverable; vector cosine ~0.89), while d1 (Pricing) scores near zero.
  2. Augment & generate: Top-k chunks enter the prompt, yielding a grounded citation: "Deleted files remain recoverable in the Nimbus trash for 30 days [Deletion Policy]." If a query has zero relevant overlap (e.g., "What is Nimbus's CEO's dog's name?"), the system abstains rather than fabricating an answer.

Common Pitfall

Blaming the LLM when retrieval failed ("Garbage In, Confident Hallucination Out"). If chunking severs an exception clause ("Enterprise only") from the main policy, or if stale/off-topic documents rank into the top-k slots, the generator will faithfully produce a fluent but wrong answer. Always evaluate retrieval quality (Recall@k: did the true source chunk appear in top-k?) separately from generation faithfulness.
