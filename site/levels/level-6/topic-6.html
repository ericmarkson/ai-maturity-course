Interpretability Tools: SHAP and LIME

Learning objective: Learner can read a SHAP-style feature-contribution chart for a single prediction and correctly state which features pushed the prediction up vs. down and by roughly how much.

Definition

Interpretability tools like SHAP and LIME explain why a model made a specific prediction by estimating how much each input feature contributed, turning a "black box" decision into a human-readable breakdown. Instead of just seeing a final score or label, you see which inputs pushed that score up, which pushed it down, and roughly by how much.

How It Works

  • Local vs. Global Interpretability: Global methods summarize average feature influence across an entire dataset (e.g., permutation importance). Local methods explain one specific prediction f(x), showing which inputs pushed that decision above or below the dataset baseline.
  • LIME (Local Surrogate Approximation): Perturbs features around input x, queries the black-box model f on those perturbed points, weights them by proximity πx, and fits a simple sparse linear surrogate g. LIME is fast and model-agnostic, though results depend on the perturbation neighborhood and kernel width.
  • SHAP (Game-Theoretic Shapley Attribution): Models each feature as a player in a cooperative game, averaging its marginal contribution across feature subsets so attributions satisfy local accuracy: f(x) = φ0 + Σ φi, where φ0 = E[f(X)] is the expected baseline. TreeSHAP computes exact Shapley values rapidly for tree ensembles; KernelSHAP approximates them for arbitrary models.

Worked Example

Suppose a loan model starts from baseline approval score φ0 = 50.0 (cutoff ≥ 50 for approval). For a specific applicant:

  • Credit Score = 760 → +13.5 pts (strong upward push)
  • Annual Income = $110,000 → +9.2 pts (upward push)
  • Debt-to-Income = 45% → −6.7 pts (downward drag)
  • Years Employed = 2 → −3.0 pts (mild downward drag)

Summing the additive contributions gives 50.0 + 13.5 + 9.2 − 6.7 − 3.0 = 63.0 (APPROVED), clearly showing Credit Score mattered twice as much as DTI for this applicant.

Common Pitfall

Treating attribution as causal advice or a guarantee of fairness. SHAP and LIME describe how the model reacted to correlated inputs, not real-world cause and effect. If a model drops protected attributes (like race) but leans heavily on ZIP code or commute time as a proxy, SHAP faithfully reports +10 pts for ZIP code without flagging indirect discrimination. Moreover, naive feature perturbation creates unrealistic off-manifold records (e.g., income = $250k, years_employed = 0) that distort surrogate fits.
