Level 5 — Intermediate+

Basic Model Deployment and Serving

Learning objective: Learner can distinguish batch vs. real-time serving scenarios from a description of a use case, and can describe the basic request/response path from client to a served model.

Definition

Deployment/serving is the process of taking a trained model and making it available so real applications can send it input and get predictions back, reliably and at scale. A served model usually sits behind an API endpoint: a client sends a request, the server runs the model (inference), and a response comes back — with real engineering questions about how fast, how many at once, and what happens when something changes.

Subtopics

  • Batch inference vs. real-time/online inference — processing many inputs together on a schedule (e.g. nightly) vs. responding to one request at a time as it arrives.
  • Wrapping a model behind an API endpoint — the client never needs to know how the model works internally, only how to call the endpoint.
  • Latency, throughput, and cost considerations — latency is how long one request takes; throughput is how many requests can be handled per unit time; the two often trade off against each other.
  • Versioning and rollback of deployed models — being able to identify which model version served a given prediction, and revert quickly if a new version misbehaves.
