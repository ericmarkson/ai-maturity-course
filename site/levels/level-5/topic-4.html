Embeddings and Vector Search

Learning objective: Compute cosine similarity between embedding vectors, explain why geometric proximity captures semantic relatedness without keyword overlap, and describe why vector indexes replace brute-force search at scale.

Definition

An embedding maps a word, sentence, or image into a dense numeric vector v ∈ ℝ^d (often 384 to 3,072 dimensions) learned so that semantically similar items sit close together in vector space. Vector search retrieves the nearest stored embeddings to a query vector—enabling retrieval by meaning even when query and document share zero exact keywords.

How It Works

1. Geometry of Meaning: Contrastive training pushes embeddings of related pairs (e.g., a question and its answer, or paraphrases) closer together while pushing unrelated pairs apart. Each axis captures latent semantic factors rather than single dictionary words.

2. Cosine Similarity & Dot Products: Text retrieval typically ranks similarity using cosine similarity, cos(a, b) = (a · b) / (‖a‖ ‖b‖), which measures the angle between vectors on a [-1, +1] scale regardless of vector length. When embeddings are normalized to unit length (‖a‖ = ‖b‖ = 1), cosine similarity simplifies to a fast raw dot product a · b.

3. Approximate Nearest Neighbor (ANN) Vector Indexes: Brute-force exact search scans every stored vector (O(N · d) per query), which becomes far too slow across tens of millions of documents. Vector databases organize vectors using ANN structures—such as hierarchical graphs (HNSW) or cluster partitions (IVF)—to visit only a tiny neighborhood of candidates and return top matches in milliseconds with ~95–99% recall.

Worked Example: Cosine Similarity Without Word Overlap

Suppose a toy 3D embedding tracks [animal, food, software]:

  • Query "famished feline": q = [0.90, 0.40, 0.00] (‖q‖ ≈ 0.985)
  • Doc A "the cat ate dinner": a = [0.85, 0.50, 0.00] (‖a‖ ≈ 0.986)
  • Doc B "patch the server bug": b = [0.00, 0.10, 0.95] (‖b‖ ≈ 0.955)

Dot product q · a = (0.90)(0.85) + (0.40)(0.50) + 0 = 0.965, giving cos(q, a) ≈ 0.965 / (0.985 × 0.986) = 0.99. Meanwhile q · b = 0.040 gives cos(q, b) ≈ 0.04. Even though "famished feline" and "the cat ate dinner" share zero literal words, vector similarity ranks Doc A near 1.0.

Common Pitfall: Replacing Keyword Search Everywhere & Mixing Model Spaces

Pure embedding search struggles with exact alphanumeric identifiers like part numbers ("SKU-8841B"), error codes ("ERR_TIMEOUT_42"), or rare names, where traditional lexical search (BM25) wins—which is why production systems often combine both in hybrid search. Also never compare vectors from two different embedding models (or versions): their coordinate axes are unaligned, so distances become meaningless.
