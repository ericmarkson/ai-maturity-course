Level 5 — Intermediate+

MLOps Fundamentals

Learning objective: Learner can list the extra components MLOps must version/monitor beyond traditional software DevOps (data, model weights, feature pipelines) and explain what "data drift" means and why it matters.

Definition

MLOps is the set of practices for managing the full lifecycle of a machine learning model in production — versioning data and models, automating retraining, and monitoring for problems — borrowed from software DevOps but adapted for ML's extra moving parts. Unlike ordinary software, an ML system can degrade even when no code changes at all, simply because the real-world data flowing into it has shifted.

Subtopics

  • Versioning — code, data, and model artifacts all need to be versioned together, not just code, so any prediction can be traced back to exactly what produced it.
  • CI/CD for ML pipelines — automated retrain/test/deploy steps, similar in spirit to software CI/CD but with data and model-quality checks added in.
  • Monitoring for data drift and model performance decay — watching whether the incoming data distribution or the model's accuracy is silently changing over time.
  • Reproducibility and rollback — being able to recreate a past model exactly, and revert to a known-good version quickly if something goes wrong.
