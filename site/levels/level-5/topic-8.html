MLOps Fundamentals

Learning objective: Explain why ML requires versioning data and weights alongside code, design CI/CD validation gates for ML pipelines, and distinguish data drift from concept drift in production monitoring.

Definition

MLOps extends software DevOps practices to the unique failure modes of machine learning systems: automating reproducible training pipelines, versioning datasets and model artifacts alongside source code, gating deployments on offline quality evals, and monitoring live traffic for silent statistical decay.

How It Works

1. Versioning the Full Artifact Triad: In traditional software, a Git commit defines program behavior. In ML, behavior depends on code + training data snapshot + hyperparameters + random seed. Versioning datasets (with hashes/lineage), feature transforms, and trained weights in a model registry makes every production prediction reproducible and auditable.

2. CI/CD Gates for ML: Automated ML pipelines run unit tests on pipeline code plus data-validation checks (missing values, schema drift) and automated model-evaluation gates—promoting a newly trained candidate only if it beats the current production baseline across key slices and latency budgets.

3. Monitoring Data Drift vs. Concept Drift: Even if zero code changes, production accuracy can erode when incoming feature distributions shift away from training data (data drift, e.g., new device types or seasonal traffic) or when the relationship between inputs and true labels shifts (concept drift, e.g., inflation altering loan-default thresholds).

4. Rollback & Retraining Loops: When monitors catch decay or a bad rollout, teams roll back instantly to the prior pinned registry version while triggering scheduled or drift-activated retraining on fresher labeled data.

Worked Example: Silent Accuracy Collapse Without a Code Change

An e-commerce fraud model deployed in January achieves 0.94 ROC-AUC. Six months later, chargebacks spike even though zero lines of serving code changed. Monitoring reveals two causes:

  • Data drift: One-click mobile wallets grew from 11% to 52% of checkout volume—an input pattern underrepresented in January's training set.
  • Concept drift: Fraudsters adapted from high-value electronics to small digital gift cards, changing which order patterns predict fraud.

Because inputs, predictions, and dataset versions were logged, the team retrains on recent labeled transactions, passes automated slice checks in CI/CD, canaries 5% traffic, and recovers 0.93 AUC safely.

Common Pitfall: Monitoring Server Health While Ignoring Model Drift

Traditional APM dashboards can show 0% HTTP 500 errors, low CPU load, and crisp 20 ms latency while a model makes progressively worse decisions every week. Never rely solely on infrastructure uptime—log input feature statistics, prediction confidence shifts, and delayed ground-truth outcomes wherever labels arrive.
