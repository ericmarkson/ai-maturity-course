Hyperparameter Tuning

Learning objective: Distinguish hyperparameters from learned weights, explain why random search often outperforms grid search on equal budgets, and protect evaluation integrity by tuning on validation splits rather than the test set.

Definition

Hyperparameters are configuration choices set around training—such as learning rate, batch size, epoch count, regularization strength, and layer width—rather than weights updated by gradient descent inside the model. Hyperparameter tuning searches systematically for the combination that minimizes loss or maximizes accuracy on a held-out validation set.

How It Works

1. Sensitivity Is Uneven: Not all hyperparameters matter equally. Learning rate typically dominates whether training converges smoothly, creeps slowly, or explodes, whereas batch size or minor width tweaks often have smaller effects once inside a reasonable range.

2. Grid vs. Random vs. Bayesian Search: Grid search evaluates every point on a fixed Cartesian grid; cost explodes exponentially (k^d) with d hyperparameters. Random search samples configurations independently across ranges, testing far more unique values along whichever dimension actually drives performance. Bayesian optimization goes further by fitting a surrogate model over completed trials to focus subsequent trials near promising valleys.

3. Schedules & Early Stopping: Instead of holding one static learning rate, schedules (like warmup + cosine decay) take large exploratory steps early and small settling steps near a minimum. Early stopping checkpoints weights whenever validation loss improves and halts training if it plateaus or starts climbing from overfitting.

Worked Example: Why 9 Random Trials Beat a 3×3 Grid

Suppose validation loss depends heavily on learning rate η and only weakly on batch size B, and your compute budget allows 9 training runs:

  • 3×3 Grid Search: Tests η ∈ {0.001, 0.01, 0.1} crossed with B ∈ {16, 32, 64}. You only explore 3 distinct learning rates—each repeated three times—missing a narrower optimum around η = 0.025.
  • Random Search (9 trials): Draws 9 independent (η, B) pairs, probing 9 distinct learning rates across the log scale—tripling coverage on the decisive axis for the exact same compute budget.

Common Pitfall: Tuning on the Test Set (and Validation Overfitting)

Using test-set scores to pick learning rates or stopping epochs leaks test knowledge into model selection, inflating reported accuracy beyond what unseen production data will achieve. Even on a dedicated validation split, running hundreds of aggressive sweeps against a small validation set can overfit to validation quirks—use cross-validation or a separate untouched final test set to keep estimates honest.
