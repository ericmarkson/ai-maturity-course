Transformer Architecture and Attention

Learning objective: Trace how scaled dot-product self-attention computes Query, Key, and Value projections, explain why dividing by sqrt(d_k) stabilizes softmax gradients, and distinguish multi-head subspaces as well as bidirectional encoder vs. causally masked decoder attention.

Definition

A transformer processes an entire token sequence in parallel using scaled dot-product self-attention, where every token directly queries every other token and blends their representations according to learned compatibility weights: Attention(Q, K, V) = softmax((Q Kᵀ) / √d_k + M) V. Because any pair of tokens interacts in a single matrix multiply rather than passing state sequentially through every intermediate step like an RNN, transformers capture long-range dependencies and parallelize cleanly across GPUs.

How It Works

1. Query, Key, and Value Projections: Each input embedding vector x_i is multiplied by three learned projection matrices to form q_i = x_i W_Q (what token i is looking for), k_j = x_j W_K (what token j advertises it contains), and v_j = x_j W_V (the payload transferred when token j is selected). Decoupling K from V allows a word like "cat" to advertise grammatical traits ("singular animate noun") via its Key while sending rich semantic traits ("furry mammal, subject") via its Value.

2. Dot-Product Compatibility & Scaling by √d_k: The raw score between token i and token j is the dot product q_i · k_j. Vectors aligned along shared feature dimensions yield large positive scores; orthogonal or opposing vectors yield zero or negative scores. However, if q and k have dimension d_k with unit-variance entries, their dot product has variance d_k (standard deviation √d_k). Without dividing by √d_k, large d_k values push logits into extreme tails where softmax saturates near 0 or 1 and gradients vanish toward zero.

3. Multi-Head Subspaces: Rather than running one attention map over the full model width d_model, transformers split into h parallel heads of width d_k = d_model / h, each with its own (W_Q, W_K, W_V). One head can track pronoun coreference, another verb-object links, and another local neighbor phrasing simultaneously before their outputs are concatenated and projected with W_O.

4. Encoder Bidirectional vs. Decoder Causal Masks: Because Q Kᵀ scores all pairs simultaneously, training avoids the RNN step-by-step bottleneck (h_t waiting on h_{t-1}). In an encoder (like BERT), mask M = 0 everywhere so every token attends bidirectionally. In an autoregressive decoder (like GPT), a causal mask sets future entries M_{i,j} = -∞ for j > i so softmax outputs exactly 0 and token i never peeks ahead during parallel training.

Worked Example: Scaled Dot-Product Attention for "it"

Suppose d_k = 4 (so scaling factor √d_k = 2) over interpretable dimensions [entity, action, pronoun/ref, spatial]. In "The cat sat on the mat", query token "it" projects to q_it = [2.0, 0.0, 2.0, 0.0] (seeking an entity/referent), and faces three keys:

  • k_cat = [2.0, 0.0, 1.0, 0.0] → raw q·k = 2(2)+0+2(1)+0 = 6.0 → scaled /2 = 3.0
  • k_sat = [0.0, 2.0, 0.0, 0.5] → raw q·k = 0.0 → scaled /2 = 0.0
  • k_mat = [1.5, 0.0, 0.0, 1.5] → raw q·k = 2(1.5) = 3.0 → scaled /2 = 1.5

Exponentiating the scaled scores gives e^3.0 ≈ 20.09, e^0.0 = 1.00, and e^1.5 ≈ 4.48 (sum 25.57), producing softmax weights of 78.6% on "cat", 3.9% on "sat", and 17.5% on "mat". Without dividing by √4 = 2, raw logits [6.0, 0.0, 3.0] yield 95.0% / 0.2% / 4.7%—already starving gradients on competing tokens at just 4 dimensions.

Common Pitfall: Leakage in Decoders & Quadratic O(N²) Cost

First, omitting the upper-triangular -∞ causal mask in a decoder lets token i attend to i + 1 during parallel training—training loss plunges artificially, then collapses at inference when future tokens are unavailable. Second, parallelization eliminates sequential step latency but not sequence-length compute: forming the full N × N matrix Q Kᵀ scales quadratically O(N²) in both compute and memory as context length N grows.
