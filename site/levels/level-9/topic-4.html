Distributed Systems for Frontier-Scale Training

Learning objective: Partition frontier-scale training across 3D/4D parallelism (ZeRO/FSDP, Tensor, Pipeline, and Context Parallelism) matched to NVLink vs. InfiniBand bandwidth, while bounding pipeline bubbles and cluster fault-recovery losses.

Definition

Frontier distributed training coordinates tens of thousands of accelerators using multi-dimensional sharding and collective communication (AllReduce, AllGather, ReduceScatter) so that massive parameter/optimizer states fit in HBM while network latency never starves tensor cores.

How It Works

Mixed-precision Adam training demands ~12–16 bytes per parameter (BF16 weights + FP32 master weights/moments + gradients), forcing frontier clusters to combine four complementary sharding axes:

  • Data Parallelism & ZeRO-1/2/3 (FSDP): Pure DP replicates weights and runs AllReduce on gradients. ZeRO-1 shards optimizer states, ZeRO-2 adds gradient sharding, and ZeRO-3 / FSDP shards parameters too—materializing weights on demand via AllGather before forward/backward and synchronizing gradients via ReduceScatter (overlapped asynchronously with compute).
  • Tensor Parallelism (TP): Splits individual linear layers column-wise then row-wise across GPUs, requiring two blocking AllReduce collectives per transformer layer. Because this sits directly on the critical path, TP is kept inside a single high-bandwidth NVLink node (typically TP ≤ 8).
  • Pipeline Parallelism (PP): Assigns contiguous layer blocks across nodes with point-to-point activation sends. Using a 1F1B (one-forward-one-backward) microbatch schedule bounds activation memory, with pipeline bubble fraction (PP − 1) / (PP − 1 + M) across M microbatches.
  • Context / Expert Parallelism & Fault Tolerance: Long contexts add Context Parallelism (Ring Attention), MoEs add Expert Parallelism (AllToAll routing), and 16k+ GPU runs use async in-memory checkpointing to absorb daily hardware failures without restarting.

Worked Example: Partitioning a 70B Run Across 80 GB H100s

At ~12–16 bytes/param, a 70B model requires 840–1,120 GB just for weights, gradients, and Adam states (plus activations). Setting TP = 8 (intra-node NVLink) × PP = 4 (inter-node InfiniBand) shards model state across 32 GPUs down to 26–35 GB/GPU, leaving ample HBM for activations and microbatches. Replicating that 32-GPU unit across DP = 64 (2,048 total GPUs) scales throughput with ZeRO-1 optimizer sharding overlapping communication behind backward passes.

Common Pitfall

Stretching Tensor Parallelism across slow inter-node links (e.g., TP = 32 over InfiniBand/RoCE): Because TP executes blocking AllReduces inside every single attention and MLP block, crossing slower inter-node fabrics crushes Model FLOPs Utilization (MFU) below 20%. Always confine TP to intra-node NVLink and scale inter-node via PP + DP/FSDP.
