Long-Context Architectures

Learning objective: Explain the mechanics of RoPE NTK/YaRN frequency scaling, sliding-window/sparse patterns, FlashAttention tiling, and Ring Attention—and diagnose why effective context length diverges from advertised window size.

Definition

Long-context architectures combine positional extrapolation (RoPE scaling), memory-hierarchy kernels (FlashAttention), distributed sequence sharding (Ring Attention), and sparse/GQA KV-cache reduction so models process 100k–1M+ tokens without HBM exhaustion or "lost-in-the-middle" retrieval collapse.

How It Works

Scaling context past pretraining lengths hits three distinct bottlenecks—compute/IO, KV-cache capacity, and positional generalization:

  • KV-cache & GQA scaling: Per-token KV cache grows linearly with context: 2 · L · nkv · dhead · nseq · bytes. Grouped-Query Attention (GQA) shares K/V heads across query groups (cutting KV memory 4–8×), while Sliding-Window Attention (SWA) caps KV retention to the last W tokens (O(n·W) cost, trading long-range verbatim recall).
  • RoPE NTK-aware & YaRN scaling: Naive linear position interpolation squeezes adjacent tokens together, hurting local resolution. NTK-aware scaling increases the rotary base θbase so low-frequency dimensions stretch to longer contexts while high-frequency dimensions preserve fine local token offsets; YaRN pairs frequency-band interpolation with attention temperature scaling and short mid-training annealing.
  • FlashAttention vs. Ring Attention: FlashAttention tiles Q/K/V blocks inside fast GPU SRAM using online softmax rescaling—avoiding materializing the O(n2) attention matrix in HBM (exact math, huge speedup, still O(n2) FLOPs). Ring Attention shards sequence chunks across P GPUs arranged in a ring, overlapping async KV block transfers with FlashAttention compute for 1M+ token training.
  • Needle-in-a-Haystack & "Lost in the Middle": Even with full attention, softmax entropy dilution and positional decay often produce a U-shaped accuracy curve—strong at prompt start/end, weak in the middle—meaning effective context lags advertised context.

Worked Example: Sizing a 70B KV-Cache at 128k Context

With L = 80 layers, dhead = 128, and nseq = 131,072 in BF16 (2 B): standard Multi-Head Attention (nkv = 64) needs 2 · 80 · 64 · 128 · 131,072 · 2 B ≈ 344 GB for a single user's KV-cache! Switching to GQA-8 (nkv = 8) + FP8 KV quantization (1 B) drops that cache 16× to 21.5 GB—making single-node serving feasible.

Common Pitfall

Confusing FlashAttention with linear-time attention, or applying YaRN zero-shot without mid-training: FlashAttention still performs O(n2) FLOPs—it speeds up memory bandwidth, not asymptotic compute. Likewise, cranking RoPE base up without even 1–2B tokens of long-context mid-training leaves middle-context retrieval brittle.
